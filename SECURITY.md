# Security Policy

## Supported versions

Security fixes are applied to the latest released version.

## Reporting a vulnerability

Use the private vulnerability reporting feature in the repository Security tab. Do not open a public issue.

Include:

1. The affected version.
2. The expected and observed behavior.
3. Reproduction steps or a minimal proof of concept.
4. The potential impact.
5. Any suggested mitigation.

Do not include live tokens, client data, private repository content, or account recovery material. If private reporting is unavailable, contact the repository owner privately and wait for a secure channel before sharing sensitive details.

You should receive an acknowledgment within seven days. Timing for a fix and disclosure depends on impact and complexity.

## Security scope

Reports about prompt disclosure, router authentication, decision tampering, safety floor bypasses, repository identity confusion, log leakage, and unauthorized external actions are in scope.

Model quality disagreements that do not bypass a documented invariant are normally product feedback rather than security issues.
